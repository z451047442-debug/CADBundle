## 五、问题 3：P0/P1 失败模式清单

### 结论

[P1] 当前最高风险不是单个绘制细节，而是“构建/注册/持久化”三条主链同时未闭合；任何一条未通过，运行时验收都没有意义。以下清单按 FMEA 给出检测、预防和降级/处置。

| ID/级别 | 失败模式 | 检测方法 | 预防 | 降级/处置 |
|---|---|---|---|---|
| F1 P0 | 编译/链接失败，无产物 | 构建退出码、完整日志、产物存在性 | 去重复源码/资源/导出；单一符号定义；CI 构建门禁 | 阻断发布，无降级 |
| F2 P0 | 只注册 1 个类，无 Utility/其余对象 | `LibNumberClasses`/`LibClassDesc` 检查；Utility 列表；导出表 | 5 个 ClassDesc 固定索引；入口测试 | 阻断发布 |
| F3 P0 | Save/Load 空实现，重开数据丢失 | 保存前/重开后字段比对；检查 `Save`/`Load` 有真实写入 | 参数块 + 引用 + 显式 chunk + 版本 + 校验 | 阻断发布 |
| F4 P0 | Class_ID 冲突/旧场景无法解析 | 静态扫描 ID；打开旧 `.max`；查看未解析对象 | 冻结 ID；旧 DLO 兼容策略；不覆盖用户场景 | 移除新插件、恢复旧 DLO；旧场景保留旧插件 |
| F5 P1 | 旧 DLO 与新插件共存冲突 | 旧 DLO 哈希/字符串/导出；启动后类列表；重复类告警 | 测试时临时移出旧 DLO；最终共存策略需裁决 | 移出旧 DLO、重启、测试后按哈希恢复 |
| F6 P1 | `IsPublic=TRUE` 或非公开类创建失败 | 创建菜单截图；`startObjectCreation`/对象计数测试 | 对象类 `FALSE`；实现可用创建路径 | 直接创建/自定义创建模式（未验证）；不建议临时公开 |
| F7 P1 | ABI/CRT/依赖缺失 | `dumpbin /headers`、`/dependents`、目标机启动 | SDK 工程属性；匹配工具集/CRT；x64 | 重建/补齐运行库；需用户确认 |
| F8 P1 | 面板关闭后创建模式残留 | 关闭/重开面板、Esc/右键中止、对象计数 | `EndEditParams` 调 `StopCreating`，清状态/销毁窗口 | 重启 Max（仅临时） |
| F9 P1 | 屏幕恒定尺寸失效 | 1×/2×/4× 截图测像素；公式审计 | 使用 `NonScalingObjectSize * GetVPWorldWidth/360` 等完整因子 | 修复后发布 |
| F10 P1 | 表格行列变化崩溃/串格/丢格 | 1×1、2×3、3×2、50×50；`cellTexts` 数量与内容比对 | 坐标映射、`SetCount` 后重取指针、边界 clamp、校验 | 修复数据并记录；崩溃则阻断 |
| F11 P1 | 缺字体/BezFont 失败导致空白或崩溃 | 指定未安装字体测试；检查回退路径 | 默认字体回退、字体名校验、捕获失败 | 回退默认字体并警告 |
| F12 P1 | 面板资源占位或 ID 冲突 | 资源审计；打开面板截图 | 完整唯一 `IDS`/`IDC`/`IDD`；移除重复 RC | 阻断发布 |
| F13 P1 | 参数块/引用/Clone 缺失，复制/撤销崩溃 | 复制/粘贴/撤销/重做；空指针检查 | 完整 refs、`MakeAutoParamBlocks`、`Clone` | 阻断发布 |
| F14 P1 | 损坏/截断 chunk、超长字符串、Unicode | 截断文件、超长字符串、中文文本 | 长度上限、版本校验、`IO_ERROR`、Unicode 安全读写 | 保持默认状态并报错，不崩溃 |
| F15 P1 | 旧场景/旧 DLO 数据不兼容 | 旧 DLO 保存场景后用新插件打开 | 保留旧 ID 或提供迁移；最终策略裁决 | 恢复旧 DLO 供旧场景使用 |

### 补充风险

- `CADText` 的 `textPosition` 与对象 TM 同时存在时，必须选择单一权威，否则加载后位置可能偏移；这是 P1/P2 边界问题。
- `textPrecision` 的格式化受区域设置影响，可能造成验收文本比较失败；属于 P2。
- 50×50 表格的字符串表编辑 UI 可能不可用；若没有二维编辑控件，验收 9 不能靠“参数块里有 `cellTexts`”通过。

## 六、问题 4：回滚计划的可执行性

### 结论

[P1] 当前阶段的回滚设计是可执行的，但尚未演练，不能标为“已验证”。由于新插件尚未安装、旧 DLO 未被修改，当前回滚成本最低；一旦复制到 `plugins`，必须按哈希和场景证据执行。

### 回滚前必须备份

| 对象 | 证据/要求 |
|---|---|
| 旧 `CADDimension.dlo` | 路径、158,720 字节、时间戳、SHA-256 `92b62a52fa288deafc0405df6d1dda4dee1756ac784382359c52969adffb963a`；复制到 `plugins` 目录之外，不删除原文件 |
| 测试 `.max` 场景 | 复制到独立备份目录；记录文件名/哈希；不得覆盖用户原场景 |
| 源码基线 | 记录提交 `cad7b7c`、分支 `ai-review-fix-2026-11-18`、工作区状态；不要在有未确认改动时覆盖 |
| 构建产物/日志 | 记录构建命令、日志、产物路径与哈希；当前无产物可回滚，只有基线日志 |
| 配置 | 本路线使用 Win32，无 Qt 配置；未发现需要修改的注册表/配置文件；若安装过程产生任何配置，需记录并纳入回滚 |

### 回滚步骤

1. 关闭 3ds Max。
2. 计算并记录旧 DLO 哈希；将其复制到 `plugins` 之外的备份目录，再从 `plugins` 移出（不是删除）。
3. 启动 Max，确认旧 CAD 类不再出现，记录截图/类列表。
4. 将新 `CADBundle.dlo` 复制到 `plugins`；复制前必须再次获得用户确认（需求 11.1.4）。
5. 启动 Max 执行验收；如果失败，关闭 Max。
6. 删除/移出新 `CADBundle.dlo`；将旧 DLO 从备份恢复回 `plugins`。
7. 用 SHA-256 和文件大小核对恢复文件与备份一致；启动 Max，确认旧类恢复、新类不出现，打开备份的测试场景。
8. 记录回滚前后哈希、时间、截图、Max 版本和场景打开结果。

### 回滚成功判据

- 旧 DLO 的 SHA-256 与 `92b62a52...963a` 一致，大小为 158,720 字节。
- `plugins` 中不再有新的 `CADBundle.dlo`。
- 3ds Max 启动无加载错误；旧 CAD 类可用；新插件类不可见。
- 旧测试场景可打开，原有对象/参数可读；没有重复类或未解析对象。
- 回滚记录包含命令、哈希、截图、日志和时间戳，可被第三人复现。

### 风险

- 若新插件使用了与旧 DLO 相同的 Class_ID，移除新插件前旧场景可能错误绑定到新类；回滚验证必须在移除新插件后重新打开场景。
- 若旧 DLO 只做了“移动”而没有可靠备份，恢复失败会直接丢失旧插件；必须保留 `plugins` 外备份。
- 若用户场景已经被新插件保存，旧 DLO 能否打开取决于 Class_ID/参数块兼容性；不能假设“恢复旧 DLO 就恢复数据”。这类场景应先复制、后测试，不得用唯一副本做实验。

## 七、问题 5：第 7/8 步门禁需要的证据，以及“未验证”风险

### 结论

[P1] 已读材料没有展开第 7/8 步的逐项判定表；以下按“构建/静态门禁”与“运行时验收门禁”给出可直接附件化的证据包。未能运行的项目必须明确标“未验证”，不能以代码存在、截图或 TODO 删除代替。

### 第 7 步：构建/静态门禁证据

必须保留：

1. 构建命令、工作目录、配置、平台、时间、执行者；完整 `baseline-build.log`/新构建日志；退出码。
2. 编译器/工具集版本、Windows SDK 版本、3ds Max SDK 路径与版本（`MAX_API_NUM_R290`/`VERSION_3DSMAX` 检查）。
3. 产物路径、大小、时间戳、SHA-256；确认只有一个 `CADBundle.dlo`。
4. `dumpbin /headers`：x64、PE DLL；`dumpbin /exports`：`LibDescription`、`LibNumberClasses`、`LibClassDesc`、`LibVersion`、`LibInitialize`、`LibShutdown`，以及需求要求的 `CanAutoDefer`；`dumpbin /dependents`：CRT/Max 依赖符合预期，无意外 Qt 依赖。
5. 静态扫描原始输出：
   - 重复宏/类/函数/资源/导出；
   - `LibNumberClasses()` 是否为 5，`LibClassDesc(0..4)` 是否完整；
   - 四个对象类 `IsPublic()` 是否为 `FALSE`；
   - `TODO`/`#pragma message`/`To be implemented`/`return nullptr` 占位；
   - `NonScalingObjectSize`/`GetVPWorldWidth`/`DrawLineProc`/`ITextObject`/`TYPE_STRING_TAB`/`P_VERSION` 的出现位置；
   - `Save`/`Load` 是否真实写入/读取。
6. 代码评审记录：每个类的方法矩阵，而不是只看符号存在。

### 第 8 步：运行时/验收门禁证据

必须保留：

1. 环境：3ds Max 2027 版本/构建号、SDK 版本、操作系统、DPI、视口尺寸；插件路径、产物 SHA-256；旧 DLO 是否在 `plugins`、旧 DLO 哈希。
2. 启动证据：Max 启动日志、插件列表截图、加载错误对话框截图（若有）、Windows 事件日志（若需要）。
3. 面板证据：Utility 列表截图；`CADAnnotatePanel` 打开截图；四个按钮标签截图。
4. 创建证据：每个类的对象数前后对比、`classof`/`GetClassName` 输出、创建模式退出截图；标注/引线三次点击坐标，文字/表格单击坐标。
5. 参数与刷新证据：修改 `showXYZ`、`textString`、`fontSize`、颜色、位置、行列数前后的截图；精确的操作步骤和时间点。
6. 屏幕恒定证据：固定视口/DPI/相机；1×/2×/4× 截图；像素测量原始数据；建议阈值 ±2 px 或 ±5%（需验收人确认）。
7. 持久化证据：保存的 `.max` 文件路径和哈希；保存前字段清单；重开后的字段清单；逐项比较结果；再次保存/重开结果；表格 `cellTexts` 的完整列表。
8. 边界证据：50×50 表格、空字符串、中文/长字符串、0/6 位精度、极端坐标、零长度点、缺失字体、截断 chunk。
9. 生命周期证据：面板关闭/重开、Esc/右键中止、复制/粘贴/撤销/重做、旧 DLO 移出/恢复。
10. 回滚证据：旧 DLO 哈希、恢复后哈希、回滚后启动截图、旧场景打开截图。

### 只能人工验证、必须标注“未验证”的项

- 箭头形状是否“正确”、文字与引线是否“美观”、网格线是否“看起来均匀”等视觉判断；除非给出几何断言或像素测量。
- “即时刷新”的主观体验；除非记录 ≤1 次重绘/500 ms 的截图或录屏。
- 面板布局、字体观感、缩放时的人工观感；除非使用像素测量。
- 旧 DLO 恢复后的旧场景“看起来正常”；除非有字段级回读。
- 任何未实际运行的创建、保存、重开、字体缺失、面板关闭、旧 DLO 冲突测试。

### 把未验证项当作完成的风险

- 代码中存在 `Save`/`Load` 或 `Display` 不代表行为正确；当前空实现就是反例。
- 删除 `TODO`/`#pragma message` 不能证明验收 13；必须配合功能矩阵和边界测试。
- 仅凭一张截图不能证明新插件生效；必须同时记录插件路径、产物哈希、类名和旧 DLO 状态，避免截到旧插件。
- 仅凭“Max 没弹错误对话框”不能证明验收 2；还需插件列表和依赖检查。
- 仅凭“保存后重开看起来一样”不能证明验收 10；必须比较 P0/P1/P2、全部参数、颜色、精度、字体、`cellTexts` 等字段。
- 若不运行验收 6/7/8/9 的量化测量，就不能在门禁报告中写“通过”；只能写“未验证/人工观察”。

## 九、可能与其他专家冲突的判断

以下仅为本人基于已读证据的判断；若与需求、UI、架构或其他视角不同，应以证据和用户裁决为准。

1. **结构重建 vs 局部修补**：我判断当前重复拼接和冲突 Class_ID 不适合逐行补丁，必须先恢复单一源码基线再实现功能；否则每一轮修改都可能引入新的重复定义。
2. **验收 11 的公式**：我判断“参数 × `NonScalingObjectSize()`”本身不足以保证缩放恒定，必须加入 `GetVPWorldWidth`/等价视口宽度因子；这与把验收 11 当作充分条件的视角可能冲突。
3. **验收 3/5–9 的可判定性**：我判断这些条款在改写为固定步骤、字段断言和像素阈值前，不能作为门禁的客观判据；仅凭视觉“看起来正确”不能签核。
4. **旧 DLO 风险级别**：我判断旧 DLO 不只是命名冲突，而是 Class_ID、旧场景解析和最终共存策略的 P0/P1 数据风险；测试前移出、测试后按哈希恢复是必要动作，但不能替代最终兼容决策。
5. **`TYPE_STRING_TAB` 持久化**：我判断不能假定参数块自动完整保存字符串表；在未运行验证前，应设计显式表格 chunk 或加载后校验，避免把“参数类型存在”当作“数据一定持久化”。
6. **验收 13 的证据**：我判断删除 TODO/占位文本不能证明“没有骨架或省略核心逻辑”；必须同时有方法矩阵、边界测试和运行时行为证据。

## 十、下一步建议

1. **先完成需求修订与裁决**：由用户/项目负责人确认屏幕恒定公式、表格行列迁移与单元格编辑方式、非公开类创建路径、Class_ID/旧 DLO 共存策略、验收 3/5–9 的量化阈值。未确认前不建议进入运行时门禁。
2. **恢复单一源码基线**：清除重复拼接；每个类一个 Class_ID；实现 5 个 ClassDesc；补齐 `.rc`/`resource.h`/`.def`；把新增文件加入 `CADBundle.vcxproj`；先让构建、导出和依赖检查稳定通过。
3. **优先完成持久化闭环**：参数块构造 + `P_VERSION` + 引用 + 显式几何/表格 chunk + 加载校验 + `Clone`；在 UI 细节之前完成“创建→保存→Reset→重开→字段比较”的最小闭环。
4. **建立可复现测试矩阵**：至少覆盖构建/导出/依赖、启动/面板/创建、四类参数编辑、缩放像素测量、表格行列迁移、保存重开、截断 chunk、缺字体、面板关闭、复制/撤销、旧 DLO 恢复。
5. **执行回滚演练并留下证据**：记录旧 DLO 哈希、移出、安装、测试、移除新插件、恢复旧 DLO、再次哈希核对；在用户确认前不要覆盖 `plugins` 或用户场景。
6. **门禁只接受可复现证据**：构建日志、退出码、产物哈希、导出/依赖表、静态扫描原始输出、截图、MAXScript/字段导出、`.max` 文件和数据比较结果；未运行的项目统一标记“未验证”，不得写成“通过”。

**总建议**：在验收 1、3、5、10、13 未转为可复现 PASS 之前，不应把当前工程描述为“完成”或“可安装”；当前最稳妥的下一步是需求裁决 + 基线结构修复 + 持久化最小闭环，而不是继续扩展 UI 或绘制细节。
